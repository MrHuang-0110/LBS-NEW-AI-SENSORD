# 电磁传感器（ELECTROMAGNETIC_SENSOR）通信协议

> 面向主机侧（NEW-AI）接入开发。本文档自包含，无需读固件源码即可实现收发。
> 固件仓库：`LBS-NEW-AI-SENSORD`｜产品宏：`ELECTROMAGNETIC_SENSOR=1`｜Keil 工程：`Project/HK32_ELECTROMAGNETIC_SENSOR.uvprojx`

---

## 1. 概述

ELECTROMAGNETIC_SENSOR 是一路**电磁吸合执行器**（电磁铁／电磁阀／继电器类负载），对主机来说语义极简：

- 主机只下发两种命令：**吸合**（`0xD1`）与**断开**（`0xD2`），两条都是**空 payload（len=0）**命令；
- 设备只上报**当前命令状态**：吸合中还是已断开（1 字节）。

| 项目 | 值 |
| --- | --- |
| ObjectID | **`0xE0`** |
| SourceID | **`0x97`**（本系列所有传感器相同） |
| 串口 | **115200 8N1**（设备侧 USART1，PA3=TX / PB4=RX） |
| 控制命令 | `0xD1` 吸合 / `0xD2` 断开（**payload 必须为空**） |
| 数据上报 | 握手后**每 6 ms** 一帧，index `0xED`，payload **1 字节** |
| 上电默认 | **断开**（两路输出均为 0，状态 `0`） |
| 失联行为 | **无超时**：吸合后即使主机不再下发任何命令也**一直保持吸合** |

输出引脚（沿用中电机 SMALL_MOTOR 的 PWM 引脚，但**不启用编码器**）：

| 引脚 | 功能 |
| --- | --- |
| PD3 | TIM2_CH1：吸合 = **100% 占空比（引脚常高）**；断开 = **0%（常低）** |
| PD4 | TIM2_CH2：本产品保留输出，**恒为 0** |
| PD1 / PD2 | 中电机的编码器输入，本产品**未初始化、未使用** |

> PWM 基频约 1 kHz，所以"100% 占空比"实际就是引脚持续拉高、线圈持续通电；本产品**不做脉冲吸合、不做自动断电**（见 §8 第 5 条）。
>
> ⚠️ **ID 提醒**：`0xE0` 在 BOOT 家族里同时是 `BOARD_MAGNETIC_SENSOR`（磁传感器）的板号（`LBS-NEW-AI-SENSORD-BOOT/Boot_All/Core/boot_config.h` 的 `BOARD_SOURCE_ID`）。若同一条串口上同时挂载"磁传感器"板与"电磁传感器"板，两者在 `frame[1]` 上**无法区分**，需要按端口/通道区分。

## 2. 帧格式

与 NEW-AI 系列其它传感器**完全一致**：

```text
[0x5A][ObjectID][SourceID][len][typeIndex][payload...][crc][0xA5]
  0     1          2        3      4          5..        n-2   n-1
```

- `0x5A` 帧头，`0xA5` 帧尾
- `ObjectID` 固定 `0xE0`（设备发出的帧）；主机下发的帧按惯例填 `0xE0`
- `SourceID` 固定 `0x97`
- `len` = payload 字节数
- `typeIndex` = 命令/上报类型
- `crc = (0x5A + ObjectID + SourceID + len + typeIndex + Σpayload) & 0xFF`，即**帧头到 payload 末尾的字节和取低 8 位**，不含 crc 与帧尾
- 总帧长 = `len + 7`

### 2.1 设备侧的校验能力（**与 PY32/G0 产品不同，务必注意**）

HK32 平台的解析器（`Project/senords.c` → `pull_data_from_queue()`）非常宽松：

| 校验项 | 设备行为 |
| --- | --- |
| 帧头 `0x5A` | ✅ 校验 |
| 帧尾 `0xA5` | ✅ 校验（判定的是"本次收到的最后一个字节"） |
| `len` / 总帧长是否自洽 | ❌ **不校验**；`len` 只用来取 payload 长度，`>27` 时按 27 截断 |
| CRC | ❌ **不校验** |
| ObjectID / SourceID | ❌ 不校验 |

结论（主机侧**必须**自己兜住）：

- 主机**自己校验 CRC 与 `len + 7 == len(frame)`**，一个 CRC 错误但帧头帧尾合法的 `0xD1`/`0xD2` **会被设备照常执行**；
- 命令天然**幂等**，所以"看不清就重发"永远安全；需要确认时以 `0xED` 回显为准（见 §6）。

### 2.2 分帧方式（影响主机怎么写串口）

设备用 **USART IDLE 空闲中断**把"一段连续收到的字节"作为一个整体交给主循环，因此：

- **一帧一次 write**，帧与帧之间留出至少 1 个字节时间的空闲（115200 下 1 字节 ≈ 87 µs，正常逐帧 write 即可）；
- 不要把一帧拆成多次 write 且中间出现空闲——前半段会成为独立碎片被丢弃；
- 半个帧、杂散字节只要后面跟着空闲，会被安全丢弃，不会影响下一帧。

## 3. 命令集（主机 → 设备）

| typeIndex | payload | 名称 | 行为 |
| --- | --- | --- | --- |
| `0x09` | ASCII `"Please Link"`（11 字节，必须逐字节一致） | 握手 | 回复 `"Play Aplication"`，**强制断开线圈**，之后开始上报 |
| `0xD1` | **空（len=0）** | 吸合 | PD3 = 100% 占空比，PD4 = 0，状态 = `1` |
| `0xD2` | **空（len=0）** | 断开 | PD3 = 0，PD4 = 0，状态 = `0` |
| `0xEE` | 任意（当前实现不检查） | 重启 | `NVIC_SystemReset()`；重启后**断开**，且需重新握手 |
| `0xED` | — | **不是命令** | 本产品的 `0xED` 只是**上报** index，主机下发会被静默忽略 |
| 其它（含 `0xDD`） | — | — | 静默忽略 |

### 3.1 握手（`0x09`）

- payload 必须是 11 字节且逐字节等于 `"Please Link"`，否则忽略。
- **设备回复字符串故意拼错**：`"Play Aplication"`（`Application` 少一个 `p`）。
  这是本系列固件的历史约定，**主机必须按这个错误拼写逐字节匹配，不要"纠正"它**。
- 握手除了开启上报，还会**强制把输出清零**（PD3/PD4 = 0，状态回到 `0`）：
  **主机重连、掉线重握手都会把已经吸合的线圈松掉**，重连后必须重新下发 `0xD1`。
- 握手成功后**不会超时**（固件里没有链路超时逻辑）；只有设备复位或收到 `0xEE` 才会回到未握手状态。

### 3.2 吸合（`0xD1`）/ 断开（`0xD2`）

- **payload 必须为空**，且要求这一帧**至少 7 字节**（完整帧头）。也就是说合法命令帧**恰好 7 字节**：
  `5A E0 97 00 D1 A2 A5` / `5A E0 97 00 D2 A3 A5`
- `len ≠ 0`（例如手滑带了一个状态字节）→ 整条命令**被忽略**：不报错、不改输出、也不在 `0xED` 上体现变化。
- 命令**幂等**：重复 `0xD1` 或重复 `0xD2` 没有任何副作用，主机可以按需重发（例如 10 Hz 重发也不会出问题）。
- **没有命令应答**：确认手段是看 `0xED` 里回显的状态（见 §4/§6）。
- **无失联超时**：`0xD1` 之后设备一直保持吸合，直到收到 `0xD2`、重新握手或复位。
- ⚠️ `0xD1`/`0xD2` 在**未握手时也会被立即执行**（固件不检查链路状态），但随后的握手会把输出清零。所以**不要在握手前发吸合命令**，否则会出现"吸合一下又被握手松开"的动作。
- 状态**不持久化**：复位后一律回到断开。

## 4. 数据上报（设备 → 主机）

| typeIndex | payload | 周期 |
| --- | --- | --- |
| `0xED` | **1 字节**，见下 | 握手后**每 6 ms** 一帧 |

payload 是一个 **packed 结构体**：

```c
typedef struct __attribute__((packed)) {
    uint8_t state;   /* 0 = 断开；1 = 吸合 */
} electromagnetic_packet_t;   /* sizeof == 1 */
```

| 字段 | 语义 | 说明 |
| --- | --- | --- |
| `state` | **命令态**，不是回执 | 设备记录的最后一条**有效**命令：`0xD1` → `1`，`0xD2` → `0`。上电/握手/复位后为 `0`。**不代表线圈真的吸合了**（没有电流/位置反馈），也不受线圈故障、供电不足影响 |
| 取值 | 只有 `0` 或 `1` | 不会出现其它值 |

**本产品的上报包只有 1 个字节**：没有 `version`、没有速度/位置/角度（与电机、颜色、灰度产品的包布局完全不同），主机解析**不要**按带版本号的布局去偏移。

时序参数：

| 项目 | 值 |
| --- | --- |
| 周期 | **≈ 6 ms**（TIM6 1 ms 节拍，每 6 拍触发一次），约 167 Hz |
| 单帧长度 | 8 字节（`len=1`，总长 = 1+7） |
| 带宽占用 | 115200 下约 0.7 ms/帧，约 12% |
| 握手前 | **零上报**（完全静默） |

## 5. 示例帧（CRC 已实测校验）

主机 → 设备：

```text
握手请求          5A E0 97 0B 09 50 6C 65 61 73 65 20 4C 69 6E 6B ED A5
吸合 0xD1         5A E0 97 00 D1 A2 A5
断开 0xD2         5A E0 97 00 D2 A3 A5
重启 0xEE         5A E0 97 00 EE BF A5
```

设备 → 主机：

```text
握手应答          5A E0 97 0F 09 50 6C 61 79 20 41 70 6C 69 63 61 74 69 6F 6E A3 A5
                                                     └── "Play Aplication" ──┘
上报 已断开       5A E0 97 01 ED 00 BF A5
上报 吸合中       5A E0 97 01 ED 01 C0 A5
```

对应 ASCII：

- `"Please Link"` = `50 6C 65 61 73 65 20 4C 69 6E 6B`
- `"Play Aplication"` = `50 6C 61 79 20 41 70 6C 69 63 61 74 69 6F 6E`

## 6. 时序与状态机

```text
主机                                      设备（电磁传感器）
 │                                          │  上电：PD3=PD4=0，state=0（断开）
 │ ── 0x09 "Please Link" ────────────────►  │  强制断开 + 开启上报
 │ ◄──── 0x09 "Play Aplication" ──────────  │
 │                                          │
 │ ── 0xD1（空 payload）─────────────────►  │  PD3 = 100%（常高）→ 吸合，state=1
 │ ◄──── 0xED {01} 每 6 ms ───────────────  │
 │           （持续吸合，主机可静默）          │  ← 无失联超时
 │ ── 0xD2（空 payload）─────────────────►  │  PD3 = 0 → 断开，state=0
 │ ◄──── 0xED {00} 每 6 ms ───────────────  │
 │ ── 0xEE ──────────────────────────────►  │  复位：线圈断开，需重新握手
```

要点：

- **握手前零上报**。主机的在线判据建议：连接后**~100 ms 内是否收到 `0xED`**（6 ms 周期下应有约 16 帧）。
- 命令延迟很小：帧结束、主循环取到该帧后立即生效（通常 < 1 ms），**最迟在下一个 `0xED` 帧（≤6 ms）里就能看到回显**。`0xED` 是**周期上报**而非事件回执，所以"发完命令立刻看状态"可能还是旧值，等一两帧即可。
- 主机 RX 必须**常开**：上行 8 字节/6 ms 与主机下行是并发的，不能"只在下发后再去读串口"，否则缓冲区会溢出。
- **连接可靠性**交给主机：设备不校验 CRC、不回 ACK。建议策略 = "下发后 20 ms 内若 `0xED` 未回显目标状态则重发"（命令幂等，重发无副作用）。
- 掉电/复位/重新握手 → 一律回到断开，主机侧应把 `state` 视为 `0` 并重新下发需要保持的吸合命令。

## 7. 主机端接入清单

1. **设备表**新增一项：`ObjectID = 0xE0`，名称如"电磁吸合传感器"，解析器复用现有多传感器框架。
2. **握手**：连接后发送 `0x09 "Please Link"`（**注意应答字符串的拼写**），握手成功后才开始收发。
3. **解析 `0xED`**：按 **1 字节 packed 结构**读 `state`，**不要**按电机（16 字节）/颜色（16 字节）/红外（2 字节）的布局解析。
4. **控制**：`0xD1` 吸合、`0xD2` 断开，payload **必须为空**（`len=0`）。
5. **UI 映射**：
   - `0xD1`/`0xD2` → 一个开关（吸合/断开）或两个按钮；
   - 把 `state` 显示为**命令态**（"已下发：吸合"），不要显示成"已到位/已吸合"这类物理回执；
   - 可选：显示"上次确认时间 / 上行帧是否在流"作为在线指示。
6. **重连逻辑**：重握手会断开线圈 → 重连成功后**自动补发**当前期望状态（重发当前值也安全）。
7. **可选**：提供"重启设备"按钮 → `0xEE`。
8. **限时吸合**（如果需要）：只能由主机自己发 `0xD2` 实现——设备侧没有任何自动断电/脉冲模式。

### 参考实现（伪代码）

```python
OBJ, SRC = 0xE0, 0x97

def build(payload: bytes, index: int) -> bytes:
    body = bytes([0x5A, OBJ, SRC, len(payload), index]) + payload
    return body + bytes([sum(body) & 0xFF, 0xA5])

LINK   = build(b"Please Link", 0x09)   # 握手
PULL   = build(b"", 0xD1)              # 吸合（payload 必须为空）
RELEASE= build(b"", 0xD2)              # 断开
REBOOT = build(b"", 0xEE)

def parse(frame: bytes):
    """返回 (index, payload) 或 None"""
    if len(frame) < 7 or frame[0] != 0x5A or frame[-1] != 0xA5:
        return None
    if sum(frame[:-2]) & 0xFF != frame[-2]:
        return None
    n = frame[3]
    if n + 7 != len(frame):
        return None
    return frame[4], frame[5:5 + n]

def parse_upload(frame: bytes):
    """0xED -> state(0/1)"""
    r = parse(frame)
    if not r or r[0] != 0xED or len(r[1]) != 1:
        return None
    return r[1][0]

# 交互
# send(LINK) → 收到 0xED{0}（未吸合）
# send(PULL) → 20 ms 内应收到 0xED{1}，否则重发
# send(RELEASE) → 20 ms 内应收到 0xED{0}
```

## 8. 常见坑（主机侧接入对照表）

| # | 坑 | 正确做法 |
| --- | --- | --- |
| 1 | 下发 `0xD1` 时手滑带了 1 个状态字节 | **payload 必须为空**，帧长恰好 7 字节；带字节 = 命令被静默忽略 |
| 2 | 纠正握手应答的拼写 | 设备回的是 `"Play Aplication"`（少一个 `p`），必须逐字节匹配，本系列历史约定 |
| 3 | 用 `0xED` 去控制线圈 | `0xED` 在本产品只是**上报** index（电机产品的 `0xED` 才是 PWM 命令），下发会被忽略 |
| 4 | 把 `state` 当成物理回执 | 它是**命令态**：没有电流/位置反馈，线圈坏了、电源掉了它照样是 `1` |
| 5 | 以为吸合会自动断开 | **无失联超时**、无脉冲模式：`0xD1` 后线圈持续通电，直到 `0xD2`/重握手/复位 |
| 6 | 依赖设备校验 CRC | HK32 设备**不校验 CRC/ObjectID/SourceID**，主机必须自己校验并用 `0xED` 回显确认 |
| 7 | 在握手前发吸合命令 | 握手会强制断开，会看到"吸合一下又被松开"；先握手再发命令 |
| 8 | 重连后忘记补命令 | 重握手/复位 = 断开，重连成功后要补发期望状态 |
| 9 | 按带 `version` 的布局解析上报 | 上报只有 **1 字节**，没有 version/速度/位置/角度 |
| 10 | 主机 RX 只在下发后读 | 上行 8 字节/6 ms 持续发，RX 必须常开 |
| 11 | 同一条串口上还有 `0xE0` 的磁传感器板 | 两个板号相同、`frame[1]` 无法区分，需按端口/通道隔离 |
| 12 | 一帧拆成多次 write 且有停顿 | 设备按 USART IDLE 分帧，一帧一次 write、帧间留空闲 |
